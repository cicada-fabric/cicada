# Native KVM filesystem preflight and IPC checkpoint

## J: filesystem-only sandbox preflight

The disposable fixture directory is historically named `sandbox-compat-tcg-20261008a`, but the actual J metadata records KVM: QEMU used `-machine q35,accel=kvm`, and the outer container exposed `/dev/kvm` with `rw` access. This was one zero-credential run of the pinned official Codex CLI 0.161.0 binary (SHA-256 `9a820c17865fa825d04db416818679a9d63bd72e50835c396f496e5684626c9c`) in image `sha256:e7540d8a8ff83952fe0dc8e46c20446d45566a2f6fb1195a98d0ab6afe216a29`.

The guest configured a named `workspace-preflight` profile extending `:workspace`, with `network.enabled = false`. Its actual CLI command was:

```sh
/bin/codex sandbox --permission-profile workspace-preflight --cd /workspace -- /bin/sh /probe.sh
```

The private guest config was:

```toml
default_permissions = "workspace-preflight"

[permissions.workspace-preflight]
extends = ":workspace"

[permissions.workspace-preflight.network]
enabled = false
```

The outer Docker envelope used network mode `none`, read-only root, `--cap-drop ALL`, `no-new-privileges`, UID 1000, supplemental KVM group 994, `/dev/kvm:rw`, 1 CPU, 2 GiB memory, and 128 pids; the guest used one vCPU and 1 GiB. The private fixture bind was read-only. The actual guest markers, in order, were `ROOT_SWITCH=PASS`, `PRE_SANDBOX_OUTSIDE_WRITE=PASS`, `WORKSPACE_WRITE=PASS`, `NATIVE_OUTSIDE_WRITE=DENIED`, `CODEX_SANDBOX_CLI_EXIT=0`, and `INIT_POSTCONDITIONS=VERIFIED`. The pre-sandbox control confirms the same UID could write the outside sentinel before invoking the native CLI sandbox.

Root's derived review records `PASS_FILESYSTEM_PREFLIGHT_ONLY`, zero API/provider/model/native Ask/Reply calls, six unchanged residents, unchanged source hashes, and removal of the exact captured container. The original aggregate terminal remains `NOT_ESTABLISHED`: its parsed CLI-exit field is null even though the exact serial capture contains `CODEX_SANDBOX_CLI_EXIT=0`. The aggregate parser first treats that line as exact membership in the expected-marker set, so its later prefix branch never assigns the exit value. The derived review confirms the marker independently; it does not rewrite or upgrade the original receipt.

This result covers only the observed workspace-write and outside-deny filesystem checks. Although network mode `none` was configured, network enforcement was not tested; guest `/proc` `Seccomp` and `NoNewPrivs` values were not measured. It does not establish general Worker isolation, native Session/context continuity, G2/G3 or full T9.

Both controllers typed the `initialize` response and recorded `initialize`, `initialized`, and `config/read`, then failed at an RPC response before any `turn/start` call (`turn_start_calls=0`). In B, the observed notification object had top-level fields `method`, `params`, and `emittedAtMs`; the cached `ServerNotification` schema declares `emittedAtMs` as optional int64. The actual notification method value was not captured, so this evidence does not identify the notification or establish a server/client protocol incompatibility. Model and provider calls are `NOT_INSTRUMENTED` in these IPC receipts; they are not claimed to be zero.

B's host/controller receipts record its wrapper group and exact owned CID/name absent, with six protected residents unchanged. One corrected C gate then ran the actual app-server process `/bin/codex app-server --stdio --disable plugins` through `/usr/bin/python3 -B /opt/ipc/zero_controller.py` in a fresh `--init` container. It recorded a typed `initialize` response, `initialized`, `config/read`, and one RPC response, then failed on the next frame before `turn/start` (`turn_start_calls=0`). That frame had top-level `method`, `params`, and integer `emittedAtMs`, no matching request ID, and no RPC error; the controller classified the method as `UNKNOWN_METHOD`, outside its three recognized methods. The actual method string was not captured, so this does not identify the event or establish a protocol incompatibility. The gate exited 1 after 8.582 seconds without timeout. The controller recorded its wrapper group absent; the host receipt records the exact owned container ID/name absent, inputs unchanged, and six protected residents unchanged. Provider/model calls remain `NOT_INSTRUMENTED`, not zero. A separate synthetic-only fixture run passed 26 tests in 0.579 seconds; it is not Native acceptance.

A separate D gate then passed the bounded initialization/config IPC check on the frozen candidate SHA-256 `7b14a15c3e6918dc265682c17948f05bcb694bf9eb2bac086b32afc0d47a38a6`, with the pinned CLI 0.161.0 and its reviewed release-source producer at `979011409de0a60b52f179721948e65531d26144`.
