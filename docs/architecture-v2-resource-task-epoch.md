# Resource Lease Task ownership fence

Resource leases capture the live Task owner epoch atomically at acquisition. Renew and the Hub-managed blob executor reload that Task in their existing serialized SQLite writer transaction and require the acquisition Group, Principal, owner epoch, CLAIMED/RUNNING state and unexpired Task claim. Native operations also require the current Task owner Endpoint to match the authenticated NativeActor. Ordinary Task revision changes within the same ownership generation remain valid.

Task release, expiry, result submission, handoff or reclaim therefore stops further renewal and managed publication using the old lease. Reclaim by the same Principal and handoff to another Endpoint are fenced by the immutable acquisition epoch. Rejection uses the existing resource-stale conflict and preserves lease deadlines, resource authority, blob and writer provenance. A write may commit before a concurrent Task transition; publication after that transition is rejected.

Store migration v58 adds acquisition provenance with default zero. Existing leases retain their historical fields and data; zero means unknown and fails closed for renewal/execution. The migration never reconstructs an old acquisition epoch from current Task state. An immutable-provenance trigger prevents replacement of the captured Task identity/epoch. Hub Store schema version is independent of Client catalog schema, wire version, contract revision and software version. The captured epoch is internal (`json:"-"`) and introduces no Client field or operation.

Acquire remains the explicit trusted-local management primitive exposed through Control. Its request has no Endpoint identity, so it checks current Task Principal ownership and captures the current generation without claiming to authenticate a native caller Endpoint. This change introduces no native Acquire API. Native Renew/Write enforce Endpoint ownership in addition to the existing transaction Guard.

Release and Quarantine remain available to the authorized resource holder for cleanup even after Task ownership is lost, including legacy unknown provenance. Task loss does not free the resource or establish that any external GPU/workspace process stopped. Physical reconciliation and advisory enforcement remain separate.
